# 执行—检验循环的评审子 agent 配置

本配置适用于这七个独立 research 技能中的执行—检验—修复—复验循环。每个技能目录都附有本文件副本，供该技能本地引用。

## 默认配置

**标注、相关性判门、文献分级、常规检验与评审子 agent 一般使用轻量模型，不开启 thinking。** 主 agent 分派时选择宿主可用的轻量模型，并通过实际运行参数关闭 thinking；不固定供应商或型号。提示词中的“不思考”不等于关闭推理。

优先选择支持关闭 thinking 的轻量模型。宿主没有关闭选项时，使用其支持的最低推理档位并说明限制，不把低档推理标为已关闭。Codex、Claude Code、OpenCode 等宿主分别使用自身支持的参数，不互相照抄参数名。

执行/生成任务按任务复杂度选模型；研究设计、策略重写、论文主线生成不因后接评审而统一降为轻量。评审环节及修复后的复验沿用本配置。既有 API runner 的模型/auth 缺省只描述该执行器，不覆盖评审子 agent 的默认配置；使用 runner 承担评审时先核对其实际配置能力，不能仅改文档就宣称 thinking 已关闭。

## 各技能中的适用位置

| 技能 | 检验/评审环节 |
|---|---|
| research-field-report | 建库门相关性判断；报告口径、内容验收及重生成后的复验 |
| research-direction-lock | 讨论产物/方向契约字段、引用依据与修正后的复核 |
| research-subtopic-retrieval | 各组合相关性判门；入库后证据契约核对与修复复验 |
| research-topic-building | 批次分析覆盖、三策略报告与逐题提取验收；单点突破课题校验 |
| research-scheme-deepening | 强相关文献筛选判断；screening 合并、deepened 契约与引用范围复核 |
| research-thesis-integration | 元素卡片、论点/故事/结构、引用及讨论记录的校验复验 |
| research-validation | 研究设计、MVE、元分析、LOOP A 分级、XE 知识库与逐步骤细化的检验复验 |

## 分派边界

能由脚本确定的数量、编号、字段、路径与集合检查继续由脚本完成；需要语义判断且分派子 agent 时应用本配置，不为机械检查额外启动模型。执行者提交产物及输入，评审者按该阶段既有契约返回通过项、具体缺口及对应位置，主 agent 据此安排修复和复验。

各阶段原有阈值、轮次上限、输入隔离、停止条件和用户裁决点仍以本阶段契约为准。轻量评审不能降低完成标准或替用户作方向、合并、跳过等人工决定。
