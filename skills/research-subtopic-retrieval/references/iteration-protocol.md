# 子问题检索判门协议（段5.2 Step 3）

步3 subagent 的输入/输出/判定标准。subagent 只读本组合输入，返回 verdict；主 agent 将 verdict 落盘，不让判门任务写共享证据库。

## 输入

- `<组合目录>/round_N_raw.json`（Scopus 首页响应，25 条）
- 当前检索式 + 组合的子问题标签
- 方向契约摘要 + 用户想法（一句话）

## 判定

读 round_N_raw.json 前 20 篇（fetch 脚本 sort=author 作者字母序，同建库判门口径），逐篇判 title + abstract 与方向/子问题是否直接相关：

```
PASS: 前20相关 ≥ 10（50%）
FAIL: 否则
```

- **相关性门不含总量阈值**；规模另按下一条窗口判定，沿用同一三轮预算
- **规模门（用户机制 2026-08-13）**：**50 < totalResults ≤ 1000 通过**；> 1000 → 自动收窄重搜；≤ 50 → 自动放宽语义群重搜。重搜与判门迭代共用 ≤3 轮预算，**自动执行、无人工确认**（只调语义群/命名变体/排除词，不加 year/doctype、不换源）
- 相关性原则：保守（宁可判不相关）、容忍术语变体、跨领域论文判不相关
- 3 轮后判门仍 FAIL 或规模仍出窗 → 该组合标「证据薄弱」：照常全量导出并追加证据 CSV，`meta.json` 记 `weak_evidence=true`，报告内注明，用户自行判断是否采信
- **并行**：全部组合的判门/迭代 subagent 并行启动（并发上限 100，尽可能大并发）
- **评审配置**：相关性判门与复验子 agent 按 [统一评审配置](review-agents.md) 使用轻量模型、关闭 thinking；query 优化任务按执行需要选模型，不统一绑定供应商。

## 输出格式

写 `<组合目录>/verdict_round_N.md`：

```markdown
# Round N Verdict（<子问题标签>）

**Verdict: PASS / FAIL**

| 指标 | 实测 | 阈值 | 通过 |
|------|------|------|------|
| 前20相关 | N | ≥10 | ✓/✗ |

## 不相关明细（FAIL 时逐篇一句原因）

## 优化建议（FAIL 时）
1. **关键词**：具体修改
2. **字段限定**：加 AND NOT 等
3. **结构**：拆括号/重组

## Final Query（PASS 时）

本轮 query 原样固定。
```

## 常见失败模式

| 现象 | 原因 | 调整 |
|------|------|------|
| 相关 < 10 但检索量很大 | 过宽 | 加 AND 限定、AND NOT TITLE(...) 排噪音 |
| 相关 < 10 且检索量很小 | 关键词偏了 | 换语义群词、加同义词 OR |
| 前20混入其他领域 | 抽象词/歧义词 | 换成过程性具体词 |
